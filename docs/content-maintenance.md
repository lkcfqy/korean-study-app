# 课程内容更新

编辑覆盖保存在 `content/context-editorial.json`，显式形态修正保存在 `content/context-morphology.json`；已经发布的语境选择保存在 `content/context-senses.json`。不要只修改 `public/course` 的生成文件。

完成来源核对、编辑覆盖和与当前输入匹配的语境选择后，在保留词典快照、形态缓存与音频的本地环境执行：

```sh
npm run content:rebuild -- --full-audio
npm run verify
```

统一重建入口依次生成语境词块、日程词数、课程目录、来源说明，再检查一致性。它不重新翻译、不运行模型、不生成语音，也不调整关卡的学习日。缺失语境选择或音频会直接报错，不能用部分生成结果替代正式验证。

韩文改变时，应同步核对整句、实际词形、词典原形三个播放入口。先准备并检查新增音频，再写入存储并由服务器读回校验，最后发布引用新音频的课程。保留已有音频以兼容旧页面。原文、修订依据、文本和音频的哈希证据应保存在审校记录中。

基础课和词典课的中文及词块解释都使用持久编辑层。词形变化可能改变某个词第一次出现的学习日，因此即使总词数不变，也必须重新计算日程中的新增词数。

独立复核覆盖须绑定实际检查的输入。来源说明页只在审校快照的课程目录哈希匹配时显示本版本有效覆盖，否则明确提示旧快照不能代表当前版本。模型报警须经语境与词典义项裁决；转写一致不能替代母语听审。

发布前还应与此前发布的 Git 版本运行 `scripts/check-course-compatibility.py --baseline-ref <实际版本>`，确认关卡及发言标识、顺序、说话人和原有答案位置保持兼容。既有进度不能因内容修订被清空。
