# 课程内容更新

编辑覆盖保存在 `content/context-editorial.json`，显式形态修正保存在 `content/context-morphology.json`；已经发布的语境选择保存在 `content/context-senses.json`。不要只修改 `public/course` 的生成文件。

完成来源核对、编辑覆盖和与当前输入匹配的语境选择后，在保留词典快照、形态缓存与音频的本地环境执行：

```sh
npm run content:rebuild -- --full-audio
npm run verify
```

统一重建入口依次生成语境词块、日程词数、课程目录、来源说明，再检查一致性。它不重新翻译、不运行模型、不生成语音，也不调整关卡的学习日。缺失语境选择或音频会直接报错，不能用部分生成结果替代正式验证。

自动选择脚本只生成本地候选。课程重建只读取版本化的 `content/context-senses.json`，忽略 `.sites-runtime/corpus/context-sense-selections.jsonl`，也不再从缓存反写版本化选择。自动候选不能因为格式有效、位于词典义项范围内或检查脚本通过而被认定为语义正确。新增或变更选择须核对完整语境和具体来源义项，在裁决记录中说明依据，再显式更新版本化文件；不要整批复制模型缓存。只改变中文、形态或候选顺序时也须核对签名及候选对应关系，不能用更新签名绕过审校。

现有版本化文件保留早期自动选择的来源标记，不代表这些历史内容均已审核。停用自动候选的隐式导入只能防止新结果混入，不能消除已经进入课程的错误。

韩文改变时，应同步核对整句、实际词形、词典原形三个播放入口。先准备并检查新增音频，再写入存储并由服务器读回校验，最后发布引用新音频的课程。保留已有音频以兼容旧页面。原文、修订依据、文本和音频的哈希证据应保存在审校记录中。

`npm run build` 先把公开资源复制到 `.sites-runtime/build-public`，检查 `content/audio-cloud-verified.json`，仅在暂存目录省略已经由本项目存储读回核验、并与本地字节完全相同的音频副本，然后让框架使用这个目录构建。必须在构建前处理，否则框架会保留已删除文件的静态路径并返回 404。原始 `content/audio` 和 `public/audio` 不删除。站点不匹配、缺少证明、新文件或哈希变化时仍保留静态副本。不能为了减小发布包而跳过存储核验、伪造证明或直接清空音频目录。迁移脚本的 `--files` 可限定要处理的文件；未列出的对象不受影响。

音频部署方式改变后，应在不含静态音频的实际生产构建中检查 `/audio/:file`。先在隔离的本地存储中装入相同文件，再运行 `python3 scripts/test-audio-delivery.py` 逐文件比较响应字节。该脚本只检查 `127.0.0.1:8787`，本地通过不冒充线上验收或母语发音审核。

基础课和词典课的中文及词块解释都使用持久编辑层。词形变化可能改变某个词第一次出现的学习日，因此即使总词数不变，也必须重新计算日程中的新增词数。

独立复核覆盖须绑定实际检查的输入。来源说明页只在审校快照的课程目录哈希匹配时显示本版本有效覆盖，否则明确提示旧快照不能代表当前版本。模型报警须经语境与词典义项裁决；转写一致不能替代母语听审。

发布前还应与此前发布的 Git 版本运行 `scripts/check-course-compatibility.py --baseline-ref <实际版本>`，确认关卡及发言标识、顺序、说话人和原有答案位置保持兼容。既有进度不能因内容修订被清空。
